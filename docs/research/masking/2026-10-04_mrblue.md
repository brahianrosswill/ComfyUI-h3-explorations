# 2026-10-04, mrblue: what the code review found that the masked lane can use

I reviewed `video_mask.py` and the song node's `source` path for mrpink this
morning, read only, on the CPU. This note is the part of that review that
bears on what mrpink and mrhf are doing now. I have rendered nothing and
looked at no clip. The review in full, with the probes and their output, is
under `internal/claude/` (`2026-10-04_mrblue_review.md`,
`2026-10-04_mrblue/`), which is not tracked.

Labels as in the README: code, measured, reported, inferred, unverified.

## 1. What can be leaned on

- measured (CPU, `masked_v2v_review_probe.py`): the frame to latent-step
  mapping in `video_mask.run_lengths` matches the video VAE's own decode plan
  at every window length tried; a subject present in one frame lands on its
  own latent step and no other; `pixel_alpha` weights exactly the frames of
  the step it is given.
- measured (same probe): `token_mask` output is unchanged by core's
  `mask_row_values`, odd grids included. The region reported, the region the
  sampler blends and the region composited are one set of tokens.
- code: `w.start` is the start of the whole window, context included
  (`loop_plan.place_windows`), so latent, mask and composite use the same
  source frames.
- code: under a spatial mask the PDD head is picked at the generating rows'
  time (`pdd_lora._row_index`), and Sol stays on, because core passes no
  attention mask whatever the denoise mask is.

So when a clip looks wrong, the mask arithmetic and the frame alignment are
not where I would look first.

## 2. A test that needs no sampling: is the remnant the decoder's or the model's

mrhf's explanation of the grey smudge
([`2026-10-04_mrhf.md`](2026-10-04_mrhf.md), section 4) has two suspects in
one sentence: "the model and the decoder can paint a remnant". They can be
told apart from files already on disk.

- code: the decoder is a ViT (`comfy/ldm/minimax/vae.py::ViT3DDecoder`) that
  attends across each clip of tokens it decodes (`decode_temporal`) and across
  a spatial tile (`tiled_decode`). A regenerated token's pixels are therefore
  a function of the kept tokens around it, at decode time, independent of
  anything the sampler did.
- code: the song node stores each window's sampled latent
  (`loop_resume.save_window`, read back by `load_window_latent`) when
  `keep_windows` is on, which it is in the shipped graph.

The test, inferred and not run:

1. Load the stored latent of the window that holds frames 438 to 538 of
   `masked_v2v_generic_30s`.
2. Encode the same source frames with the masked pixels filled (the fill
   mrpink is building), and take that encode's values for the kept tokens
   only. The regenerated tokens stay exactly as sampled.
3. Decode, composite as the node does, and run mrhf's `cell_probe.py` on the
   x 640 to 703 cells.

What each outcome buys:

- The smudge goes: it was painted at decode. Then renders already made can be
  repaired by decoding again, with no sampler pass.
- The smudge stays: it is inside the regenerated tokens, so the model put it
  there, and only a new sample with the fill can remove it.
- It fades and does not go: both.

The fill before the encode fixes both paths at once in a new render, so this
test does not gate mrpink's build. It says whether old renders are
recoverable and which half of the explanation is true.

## 3. The two-sampler graphs can carry the mask with one node

- measured on a stub model (same probe, through core's own `KSAMPLER` and
  `KSamplerX0Inpaint`, euler, a mask uniform per patch): as wired, the second
  sampler takes the first one's still-noisy latent as the plate, and the kept
  rows come out noisy. Replacing the kept rows of the latent between the two
  samplers with the clean plate, `mask * first_pass + (1 - mask) * plate`,
  gives the clean plate back, shows the model the clean plate, and leaves the
  generating rows identical to the unfixed run and to a one-sampler run.
- code: the mask reaches the second sampler unasked, because
  `SamplerCustomAdvanced` returns a copy of the latent dict it was given.
- inferred: the frozen audio needs the same restore in the same node.
- unverified: on H3 itself. Nothing was sampled on the real model.

This is what would let the daily graphs (PDD8 then the FlashGen finish) be
the base, which is what the owner first asked for. It is listed as owed in
`docs/wiki/next_steps.md`. I can build the node and its CPU check from the
probe.

## 4. A soft band, which core already supports and nothing here uses

`video_mask.token_mask` is binary on purpose. For the record of what the
other choice does:

- code: a row with mask value m runs at `m * sigma`
  (`comfy/ldm/minimax/model.py::_forward`, `rows_t`), its velocity is scaled
  by m, and each step's output for it is `m * model + (1 - m) * plate`
  (`comfy/samplers.py::KSamplerX0Inpaint`). So a band of tokens beside the
  subject at a value between 0 and 1 is a blend in latent space, every step,
  between what the model wants there and the source.
- code: PDD's head selection already handles a graded mask
  (`pdd_lora._row_index`, whose docstring says it was driven on one).
- inferred: such a band is another way to weaken the original's trace in the
  tokens next to the mask, and to let the light on the plate beside the
  subject follow the replacement. It also lets the model alter source pixels
  in that band, which the composite would then have to keep or discard.
- unverified, and second to the fill: the fill removes the cause, this
  dilutes it.

## 5. Two attributions nobody has made

- unverified: whether sparse attention or the distill contributes to any
  artefact. Sol's exact range covers the rows ahead of the video span; the
  kept plate rows are inside the span and are routed like any generating row.
  The tau settings were graded on videos where every row generates. One arm
  with dense attention at the same window and seed would say whether Sol is
  in the picture; I have no evidence that it is.
- code: `MiniMaxH3DenoiseMaskProbe` reports the mask the sampler was actually
  handed, if a render and the mask ever seem to disagree.
