# SAM 3.1 as Meta built it, and what core's port does instead (2026-10-06, mrsun)

A reading, made the day the owner decided that SAM 3 should be used in this
pack the way Meta built it. Nothing was run: no model was loaded and no media
was opened. It answers three questions: what
Meta's pipeline does frame by frame, where core's port departs from it, and
what a port would stand on.

How each thing is known, in the folder's labels. **code** means I read the
line cited. **reported** means a read-only helper of this session read it and
I did not; those are few and marked. **inferred** is reasoning from the code.

What was read, and at which commit:

- Meta's repository, `coderef/sam3` at `2345a4a`, tree clean.
- ComfyUI core at `7a5dad695`; its SAM 3 files were last changed by
  `203579918` (`comfy_extras/nodes_sam3.py`, `comfy/ldm/sam3/`).
- `coderef/meta-sam` at `cdf2e8b`: the wire protocol of Meta's hosted SAM 3

  model to a user.
- An earlier reading by another session, untracked, covers the paper, the
  phrase vocabulary and the prompt types. This page does not repeat it.

## 1. Meta's pipeline for a video and one phrase

**The entry point** is `coderef/sam3/sam3/model_builder.py::build_sam3_multiplex_video_predictor`
(line 1070; its docstring calls it the recommended one). It builds a detector,
a multiplex tracker and a model that joins them, and wraps them in
`coderef/sam3/sam3/model/sam3_multiplex_video_predictor.py::Sam3MultiplexVideoPredictor`. (code)

**A session** starts on a directory of numbered frames, a video file or a
list of images, not on tensors (reported: `coderef/sam3/sam3/model/io_utils.py`). One phrase per
session: adding a text prompt resets the session first (reported:
`coderef/sam3/sam3/model/sam3_multiplex_tracking.py::add_prompt`). The predictor enters a
bfloat16 autocast when it is built and never leaves it
(`coderef/sam3/sam3/model/sam3_multiplex_video_predictor.py:51-52`). (code)

**Each frame**, in order:

1. The detector runs. Its class score is multiplied by the presence score:
   `outputs_class.sigmoid() * prob_dec_presence_out`
   (`coderef/sam3/sam3/model/sam3_image.py:345-353`, switched on by
   `supervise_joint_box_scores=True`, `coderef/sam3/sam3/model_builder.py:1162`). (code)
2. Detections are kept above `score_threshold_detection` and reduced by NMS
   at `det_nms_thresh` on intersection-over-minimum
   (`coderef/sam3/sam3/model_builder.py:1170-1172`). (code)
3. They are associated with the tracker's current masks by overlap alone,
   `coderef/sam3/sam3/model/sam3_video_base.py::_associate_det_trk_compilable` (lines 163-213).
   The overlap is intersection-over-minimum when `use_iom_recondition` is
   set, as it is for 3.1. A track is matched when any detection overlaps it
   by `iou_threshold_trk`. A detection is a new object when it scores at
   least `new_det_thresh` and overlaps no track by `assoc_iou_thresh`. (code)
4. New objects take the next id; ids are never reused (reported). At the cap,
   new detections beyond the free slots are dropped, highest scores kept, and
   detection goes on (`coderef/sam3/sam3/model/sam3_video_base.py:60-76`). (code)
5. A keep-alive counter per track goes up when matched and down when not,
   between `min_trk_keep_alive` and `max_trk_keep_alive`
   (`coderef/sam3/sam3/model/sam3_multiplex_base.py:2218-2225`, defaults at 228-230). (code)
6. On frames whose index is a multiple of `recondition_every_nth_frame`, a
   confident detection that overlaps a track can rewrite that track's mask
   (`coderef/sam3/sam3/model/sam3_multiplex_base.py:1133-1151` for the trigger; the conditions, a
   detection score of 0.8, the overlap of `iom_thresh_recondition` and a
   confident tracker, are reported). (code, reported)

**A new object is not shown at once.** Output runs `hotstart_delay` frames
behind; inside that window an object unmatched or a duplicate for
`hotstart_unmatch_thresh` or `hotstart_dup_thresh` frames is removed
(reported). With `masklet_confirmation_enable`, as 3.1 sets it, an object
stays hidden until matched on
`masklet_confirmation_consecutive_det_thresh` consecutive frames
(`coderef/sam3/sam3/model/sam3_multiplex_base.py:248-251`). (code for the count, reported for the
mechanism)

**The 3.1 builder's values** (`coderef/sam3/sam3/model_builder.py:1166-1190`, code):

| setting | value |
|---|---|
| `score_threshold_detection` | 0.4 |
| `det_nms_thresh`, with `det_nms_use_iom` | 0.1 |
| `assoc_iou_thresh` (a detection is new below this) | 0.1 |
| `new_det_thresh` | 0.65 |
| `hotstart_delay`, `hotstart_unmatch_thresh`, `hotstart_dup_thresh` | 15, 8, 8 |
| `recondition_every_nth_frame` | 16 |
| `iom_thresh_recondition`, with `use_iom_recondition` | 0.5 |
| `masklet_confirmation_enable` | on |
| `max_num_objects` (the builder's argument, line 1073) | 16 |

Left at the class's defaults (`coderef/sam3/sam3/model/sam3_multiplex_base.py:217-251`, code): a track
is matched at 0.5; keep-alive starts at 0 and runs from -4 to 8; confirmation
needs 3 frames.

**What it returns**, per frame: object ids, one score per object (its first
detection's, not the frame's), boxes and binary masks (reported). The example
notebook colours an object by `COLORS[obj_id % len(COLORS)]`
(reported: `coderef/sam3/sam3/visualization_utils.py`).

**Two things in the released 3.1 code that are not what they look like**
(code, both read after a helper flagged them):

- *The suppression of an unmatched track is computed and never applied.*
  `_process_hotstart_gpu` returns it (`coderef/sam3/sam3/model/sam3_multiplex_base.py:2302-2309,
  2353, 2372`), the caller binds it at line 1063, and nothing in the file
  reads it again; only the removal mask is used (lines 1195, 1220). The
  routine that fills `suppressed_obj_ids`, `_process_hotstart`, is called
  only on the SAM 3 path (`coderef/sam3/sam3/model/sam3_video_base.py:825`). So in 3.1 a track the
  detector stops matching stays in the output while its mask is non-empty.
- *The predictor's session start passes a keyword the model does not take.*
  `Sam3BasePredictor.start_session` puts `offload_state_to_cpu` into the
  arguments of `self.model.init_state` (`coderef/sam3/sam3/model/sam3_base_predictor.py:137-154`);
  `Sam3MultiplexVideoPredictor` does not override it, and the 3.1 model's
  `init_state` has neither that parameter nor `**kwargs`
  (`coderef/sam3/sam3/model/sam3_multiplex_tracking.py:2218-2226`). As written that raises. Not run.

## 2. At a cut

Meta's code has no handling of a cut, a shot change or any discontinuity
(reported, by search of the repository). Its video data was checked to have
none (the paper, as the earlier reading cites it).

What the logic above does at a hard cut (inferred, and the one question here
a run is needed for): the tracks carry on, since nothing removes one after
the hotstart window. A person in the new shot who overlaps a stale mask by
`assoc_iou_thresh` is taken for that track, and the next periodic rewrite can
put them under the old id. Others get new ids while slots last. A person who
comes back gets their old id only if the old track happens to re-segment
them.

Meta's own protocol document says how a caller is meant to deal with it. A
request is either one noun phrase or object prompts, never both; an object
prompt is an id with one box and positive or negative points on a named
frame, and "the same id on another frame prompts the same object again on
that frame"; masks are not accepted as prompts
(`coderef/meta-sam/protocol/sam3.md`, "SAM API input"). (code) So the answer
to a discontinuity is the caller's: prompt the same id again after it.

## 3. Core's port

**What core has.** The networks: the trunk, the detector with its presence
head, and both trackers, the SAM 2 style one and the 3.1 multiplex one
(`comfy/ldm/sam3/`). It loads the checkpoint through its ordinary loader and
both nodes call `load_model_gpu`, so the model comes on and off the card under
core's model management (reported: `comfy/supported_models.py`,
`comfy_extras/nodes_sam3.py`).

**What core does not have** is Meta's session logic.
`comfy/ldm/sam3/tracker.py::track_video_with_detection` and
`_match_and_add_detections` are a shorter one of core's own (code, lines
1578-1643 and 1686-1775):

| | Meta, 3.1 | core |
|---|---|---|
| presence score | multiplied into every detection score | computed, then dropped: `forward_from_trunk` discards it (`comfy/ldm/sam3/detector.py:495-509`) |
| a detection is kept | above 0.4, NMS at 0.1 | above the node's `detection_threshold`, NMS at 0.5 |
| a track is matched | overlap of 0.5 | overlap of 0.5 |
| a detection is new | score of 0.65 and no overlap of 0.1 | no overlap of 0.5 |
| a new object appears | after the hotstart window, and once confirmed | on the frame it is detected |
| duplicates and never-matched objects | removed inside the hotstart window | kept |
| at the cap | new detections dropped, detection goes on | detection skipped for the rest of the clip (line 1691), which also stops the counters and the rewrite |
| the cap's default | 16 | 4 on the node (`comfy_extras/nodes_sam3.py:276`) |
| a track the detector stops matching | stays (the suppression is not applied) | blanked in the output while its counter is at or under zero (lines 1770-1773) |
| a confident detection rewrites a tracked mask | every sixteenth frame, with conditions | on every detection frame, at a score of 0.8 and an overlap of 0.5 |
| prompts | a phrase, or points with an id | a phrase, or a mask on the first frame |

Core's keep-alive range is Meta's class default, and its comments point at a
reference in three places (`comfy/ldm/sam3/tracker.py:552, 1164, 1590`), so
core's logic reads as a reduction of Meta's and not as a different design.

**The three complaints in `subject_track.py`'s docstring, attributed:**

- *Across a cut the tracker starts new objects.* Meta's behaviour too.
  Neither has anything for a cut.
- *An object cap that detection stops at for good.* Core's. Meta keeps
  detecting and only refuses new objects.
- *A detector mask that overwrites the tracked one on a confident frame.*
  Meta's design, which core applies on every frame where Meta applies it on
  one in sixteen.

## 4. What a port would stand on

**Meta's session logic over core's loaded networks** is the cheapest faithful
port: no second copy of the weights on the card, and the pack's repacked
checkpoint loads through core as it does now
(`bench/convert_sam3_checkpoint.py` changes the container and no weight). Two
things it costs, and one it assumes:

- It calls methods of core's tracker and detector that are private by name:
  the per-frame track step, the memory encode, adding objects, and `_detect`,
  the one call that still returns the presence score. Core can move them.
  Every such call belongs in one adapter with a check that asserts their
  signatures.
- Meta's reference runs in bfloat16 autocast; a comparison has to say which
  dtype each side ran in.
- It assumes core's forward passes compute what Meta's do. Nobody has shown
  that. One difference is already known from the earlier reading: core keeps
  every conditioning frame where Meta attends to a few.

**What Meta's code needs to run here as the reference** (read from its
`pyproject.toml`, its imports and the ComfyUI venv with
`importlib.metadata`; nothing was installed):

- Its README asks for Python 3.12 or higher, PyTorch 2.7 or higher and CUDA
  12.6 or higher, and its classifiers stop at 3.12.
- Missing from the ComfyUI venv: `timm`, `ftfy` (pinned to one version),
  `iopath`; `pkg_resources`, which `coderef/sam3/sam3/model_builder.py` imports at line 8 and
  the venv's setuptools no longer ships; `flash_attn_interface`, which the
  3.1 builder turns on by default (`use_fa3`) and takes an argument to turn
  off. Declared conflict: numpy below 2.
- Its loader reads Meta's original `.pt`
  (`coderef/sam3/sam3/model_builder.py:539-541, 1050-1053`).
- No memory figure is stated in its README or its release notes.

So the reference gets an environment of its own and the ComfyUI venv is left
alone.

## 5. What happened next, the same day

Two routes to "as Meta built it" were on the table by the evening, and
neither is built:

- **Meta's session logic re-expressed over core's networks**, proven against
  Meta's code run as a one-off reference. Section 4 is what it would stand
  on. Its first step was to be a spike: Meta's detector and tracker against
  core's on the same frames, and Meta's predictor across one hard cut.
- **Meta's own inference code copied into the pack under its licence**,
  edited only where it must be, with core's SAM 3 nodes no longer called. The
  owner asked why not, and it is the simpler reading. Its first step is a
  different spike: whether the files the 3.1 video predictor needs can import
  and build the model in the ComfyUI venv without installing anything.

Agreed for either route: the result is one value every node downstream reads,
shaped as Meta's protocol shapes its output (per frame and per object a
stable id, a box, a mask and a confidence), with a colour-coded video of it;
one session per shot, which is ours and not Meta's, because Meta's logic
keeps stale tracks at a cut; and this pack's cuts, pick, recognition after a
cut, corrections and shot table on top, since Meta has no answer for them.

The work passed to another session that evening. This page is the reading it
starts from; what was decided belongs in `docs/wiki/decisions.md` once a
spike has said which route stands.
