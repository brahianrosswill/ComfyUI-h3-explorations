📊 DiT Block Relative Error Profile (Blocks 0 to 49)

Calculated via DuckDB SQL aggregation on sol_probe_cells. Notice how the middle layers (Blocks 38–43) and tail blocks (48–49) exhibit high sensitivity to block-sparse attention pruning.

SELECT block, ROUND(AVG(rel_l2)*100, 2) AS avg_rel_l2_pct, ROUND(MIN(cos), 4) AS min_cosine FROM sol_probe_cells GROUP BY block ORDER BY block;
Hover over bars to inspect Block Relative L2 error. Red bars highlight blocks with >12% relative error.
🔍 Sensitive Attention Heads (Outliers)

Unnesting metrics.per_head struct array in DuckDB isolates individual attention heads where channel collapse occurs:

WITH unnested AS ( SELECT block, unnest(per_head) AS h FROM sol_probe_cells ) SELECT block, h.head, ROUND(MIN(h.cos), 4) AS min_cos FROM unnested GROUP BY block, h.head ORDER BY min_cos ASC LIMIT 8;

🎬 PackedLayout Modality Sensitivity

Querying sol_probe_segments reveals which sequence modalities suffer most from sparse pruning:

SELECT segment_kind, ROUND(AVG(seg_rel_l2)*100, 2) AS avg_l2_pct, ROUND(MIN(seg_cos), 4) AS min_cos FROM sol_probe_segments GROUP BY segment_kind ORDER BY avg_l2_pct DESC;

💡 Key Finding: Text tokens suffer the highest relative L2 error (~20%), explaining why conditioning sink blocks (sink_conditioning='exact_kv_and_rows') are vital to preserve prompt adherence.
⚡ Step Trajectory & Routed Density (sol_observe)

DuckDB query joining step schedule with router block density and peak CUDA memory footprint:

SELECT step, ROUND(AVG(mean_routed_density)*100, 2) AS routed_pct, ROUND(MAX(peak_vram_mb), 1) AS vram_mb FROM sol_observe_calls WHERE route = 'sol' GROUP BY step ORDER BY step;
